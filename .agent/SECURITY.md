# SECURITY.md — Security Rules

## Authentication

- **MVC**: Cookie authentication (browser sessions).
- **API**: JWT Bearer authentication.
- **Identity**: ASP.NET Core Identity for user management.
- Passwords hashed by Identity (built-in PBKDF2).

## Authorization

- Roles: `Admin`, `Organizer`, `Attendee`.
- `[Authorize]` on protected controllers/actions.
- `[Authorize(Roles = "Admin")]` for admin-only endpoints.
- User can only access their own resources (ownership checks in services).

## Secrets

> Never place secrets, API keys, passwords, tokens, private credentials, or production connection strings into source code or documentation.

- Use `appsettings.json` with placeholders.
- Use User Secrets for local development.
- Use Environment Variables in production.
- JWT key must be at least 32 characters.

## CSRF Protection

- All POST forms use `[ValidateAntiForgeryToken]`.
- Anti-forgery tokens generated by ASP.NET Core.

## CORS

- Currently not configured (single-origin setup).
- Add CORS policy if API needs cross-origin access.

## XSS Prevention

- Razor Views auto-encode output by default.
- Use `@Html.Raw()` only with trusted content.
- Never render user input without encoding.

## SQL Injection

- Entity Framework Core uses parameterized queries.
- Never use raw SQL with string concatenation.
- Use `FromSqlRaw` with parameters if raw SQL is needed.

## Input Validation

- Model validation attributes on DTOs and ViewModels.
- Server-side validation on all forms.
- `[Required]`, `[StringLength]`, `[Range]` used consistently.

## File Uploads

- No file upload feature currently implemented.
- If added: validate file types, size limits, scan for malware.

## Password Policy

- Minimum 6 characters.
- Requires digit, lowercase, uppercase.
- Does not require special character.
- Lockout disabled (development mode).

## Logging

- Never log sensitive data (passwords, tokens, credit cards).
- Log authentication events (login, logout, failed attempts).
- Log authorization failures.

## Dependencies

- Monitor NuGet packages for vulnerabilities.
- Use `dotnet list package --vulnerable` to check.

## Security Checklist for Code Changes

- [ ] No secrets hardcoded
- [ ] Input validated
- [ ] Authorization attributes present
- [ ] Anti-forgery tokens on forms
- [ ] No raw SQL with concatenation
- [ ] Sensitive data not logged
- [ ] No XSS vectors (unescaped user input)
- [ ] File uploads validated (if applicable)
